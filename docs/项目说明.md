# SZ50 AIR 远程管理工具：项目说明

> 根据当前仓库代码与根目录 [README](../README.md) 整理，日期：2026-09-24。本文说明仓库结构和开发流程；README 中的设备运行状态记录截至 2026-09-22，本次未重新连接设备核验。

## 1. 项目是什么

本项目为 SZ50 AIR 设备扩展一套浏览器管理界面。它保留设备原有的 Web、AT 和终端服务，在前面加入 Go 编写的认证网关，并提供设备管理、状态监测、Wi-Fi、流量、代理、充电和系统设置等功能。

主要由三部分组成：

| 部分 | 仓库位置 | 作用 |
| --- | --- | --- |
| 认证网关及扩展 API | `admin-auth/` | Go 服务，统一认证、反向代理、采样和控制设备功能 |
| 管理界面 | `ui/` | HTML、CSS、JavaScript、页面模板和生成脚本 |
| 原始工具与设备文件 | `原始工具/` | ADB、驱动、原始脚本和备份；主要用于追溯与设备维护 |

`.tools/` 保存本机 Go 工具链、测试辅助文件及部分部署资源。根目录 `README.md` 记录了更详细的实现、实机排查、升级历史和已知限制。

### 使用入口

连接设备热点或 USB 网络后，按设备实际网关地址打开管理页；现有 README 使用 `http://192.168.0.1/` 作为访问示例。输入设备当前的管理账号和密码后，可在侧边导航进入网络概览、网络与 SIM、Wi-Fi 设置、连接设备、设备监测、流量管理、AT 控制台、网页终端和系统设置。测速、代理与充电功能也有对应的页面入口。页面数据来自设备实时接口，部分操作（如切换信道、修改充电规则、开关代理）会立即改变设备状态。

## 2. 运行架构

```text
浏览器 / API 客户端
        │
        ▼
设备上的 iptables 端口重定向
        │
        ▼
admin-gateway（登录、会话、权限检查）
        ├─ /air-api/* → 网关内的 Go 功能模块
        └─ 其他路径   → 设备原有 Web / AT / 终端服务
```

设备端 `start.sh` 检查 Wi-Fi 驱动与 ConnMan，设置端口重定向及访问规则，然后启动 `supervise.sh`。守护脚本每 3 秒检查 `admin-gateway`、Wi-Fi 驱动和 ConnMan。开机入口是设备上的 `/etc/rcS.d/S38admin-auth`；README 说明它是 `start.sh` 的物理副本，因此修改启动逻辑时两处需要同步。

| 网关监听端口 | 后端本机端口 | 用途 |
| --- | --- | --- |
| `18080` | `80` | 主 Web 页面；网关还将 `/api/*` 发往本机 `8080` |
| `18081` | `8080` | 原有 AT 服务 |
| `17681` | `7681` | 网页终端 |
| `19998` | `9998` | 原有附加服务 |

浏览器访问设备管理地址时，原服务端口经设备端规则转到认证网关。未登录的页面访问会跳到 `/air-login`；脚本/API 客户端可使用 Basic 认证。浏览器会话由网关签名，默认有效期 8 小时；重启网关或修改管理密码后，已有会话失效。网关从设备的 `/home/root/admin-auth/credentials.json` 读取认证信息。

## 3. 功能和代码入口

| 功能 | Go 代码 | 前端代码 / 页面 | API 入口示例 |
| --- | --- | --- | --- |
| 登录、退出、修改密码 | `gateway.go`、`login_page.go`、`credentials.go` | `ui/index.html`、登录页由 Go 返回 | `/air-login`、`/air-logout`、`/air-api/credentials` |
| 连接设备、备注、限速与配额 | `devices.go`、`traffic.go` | `air-devices.*`、`templates/settings/devices.html` | `/air-api/devices`、`/air-api/traffic` |
| CPU、内存、温度与蜂窝信号 | `monitor.go`、`signal.go` | `air-monitor.*`、`air-trend.*` | `/air-api/monitor` |
| Wi-Fi 信道雷达和开关 | `wifi_radar.go`、`wifi_security.go` | `air-wifi-radar.*`、`templates/settings/z50_air_wifi.html` | `/air-api/wifi/radar`、`/air-api/wifi/channel`、`/air-api/wifi/power` |
| 透明代理、节点和实时网速 | `proxy.go`、`proxy_rules.go`、`proxy_iptables.sh` | `air-proxy.*`、`templates/settings/proxy.html` | `/air-api/proxy`、`/air-api/network/speed` |
| 流量统计 | `traffic.go`、`proxy.go` | `air-page-liuliang.*`、`templates/settings/liuliang.html` | `/air-api/traffic`、`/air-api/traffic/daily` |
| 智能充电 | `charge.go` | `air-charge.*`、`templates/settings/charge.html` | `/air-api/charge` |
| SFP 硬件加速控制 | `system.go` | `air-system.*`、`templates/settings/system.html` | `/air-api/system/sfp` |
| 测速 | `speedtest.go` | `air-speedtest.*`、`templates/settings/speedtest.html` | `/air-api/speedtest` |

Go 网关在 `gateway.go` 中按路径把 `/air-api/*` 分发给相应模块，未匹配的请求交给原服务。原有设备 CGI 和 AT 接口仍在界面中使用，因此排查页面数据时也要查看 `/cgi-bin/*` 和 `/api/*` 请求。

## 4. 文件从哪里来、部署到哪里

`ui/templates/` 是部分页面的编辑入口。`ui/build_ui.py` 生成 `ui/index.html`；`ui/build_inner.py` 从模板生成 `ui/inner-pages/*.html`，并复制部分无需转换的模板。修改这些页面应先改模板，再重新生成，避免下次构建覆盖手工改动。`ui/air-*.js`、`ui/air-*.css` 为前端模块源码，`ui/layui/`、`ui/vendor/` 和 `ui/at-vendors.*` 是运行依赖。

设备上主要放置位置：

| 本地内容 | 设备位置 |
| --- | --- |
| `admin-auth/admin-gateway`、启动与守护脚本、代理规则脚本 | `/home/root/admin-auth/` |
| 主界面和大部分静态资源 | `/webui/` |
| 生成的设备设置页面 | `/webui/html/` |
| AT 控制台页面与相关资源 | `/home/root/8080/dist/` |

设备运行时会在 `/home/root/admin-auth/` 保存 `credentials.json`、`devices.json`、`traffic.json` 等配置或统计文件。`credentials.example.json` 仅是格式示例，不能覆盖设备已有凭据。

## 5. 本地构建与检查

开发环境按仓库现状使用 Windows PowerShell、Python 3 和 Go。本项目 Go 代码采用 `GO111MODULE=off`，构建脚本先执行 Go 测试，再交叉编译 Linux ARM64 二进制；项目内的 `.tools/go/bin/go.exe` 可作为本地工具链。

在项目根目录运行：

```powershell
./admin-auth/build.ps1
python ui/build_ui.py
python ui/build_inner.py
```

只检查 Go 代码时：

```powershell
$env:GO111MODULE = 'off'
.tools/go/bin/go.exe test ./admin-auth
```

`admin-auth/*_test.go` 是后端单元测试。`.tools/test_*_ui.py` 等脚本用于本地浏览器模拟验证，通常需要 Python Playwright 和 Chromium；具体脚本清单及用途见根目录 README。仅修改说明文档时无需构建或连接设备。

## 6. 设备部署与维护要点

仓库中的 `admin-auth/deploy_devices.py` 是现有整套更新脚本。它通过 USB ADB 传输文件、在设备上创建回滚点，并在部署后检查接口与页面；执行它会修改真实设备，应在确认设备连接、备份和待发布文件后使用。仅 Wi-Fi 雷达等局部更新还有 `deploy_radar.py` 等专用脚本。部署细节及回退路径以根目录 README 和对应脚本为准。

维护时特别注意这些联动关系：

1. `start.sh` 与设备上的 `/etc/rcS.d/S38admin-auth` 要同步，否则手动启动与开机启动可能使用不同规则。
2. 智能充电的 Go 守护与原厂 `cgi_charge.sh` 都能写充电控制节点；调整阈值时要核对 `charge_rule.json` 与 `/webui/traffic.ini`。
3. 透明代理和认证入口都会操作 iptables；调整端口或规则时要检查 `start.sh`、`proxy_iptables.sh` 和设备当前规则。
4. 单设备流量和限速依赖 `tc` 统计与整形。SFP 硬件加速可能绕过部分软件计数路径，修改统计逻辑时需要实机复核。
5. Wi-Fi 的真实射频信道以驱动日志及 `/data/vendor/wifi/hostapd/softap.ini` 为重要依据；ConnMan 配置值不一定代表已生效信道。

根目录 [README](../README.md) 的“运行架构”“耦合与冲突风险”“设备部署”及“升级记录”包含更详细的实机背景。本文适合先建立整体认识，再按要修改的模块查阅源码和 README 专项记录。
